## 命令行试一下

要求 Node ≥ 20，零依赖，在仓库根目录运行。下面是 2026-09-15 用默认参数实测的输出。

| 命令 | 结果 |
|---|---|
| `node scripts/compile-table.mjs --table examples/majority3.table.json --name majority3` | 6 NAND，深度 5，8/8 行精确 |
| `node scripts/compile-table.mjs --table examples/adder4.table.json --name adder4` | 4 位加法器带进位：38 NAND，深度 23，512/512 行精确 |
| `node scripts/compile-grid.mjs --map examples/grid-demo.map.json --labels stay,left,right,jump --name grid-demo` | 40 NAND，深度 16，256/256 行精确 |
| `node scripts/compile-fsm.mjs --spec examples/counter.fsm.json --name counter` | 带使能的 2 位计数器：10 NAND + 2 LATCH，8/8 个（输入，状态）组合精确 |
| `node scripts/compile-fsm.mjs --spec examples/traffic-light.fsm.json --name traffic-light` | 红绿灯：14 NAND + 2 LATCH，8/8 个组合精确 |

也可以不写文件，直接给表达式：

```
node scripts/compile-table.mjs --fn "(x&1)^((x>>1)&1)" --nIn 2 --nOut 1 --name xor2
node scripts/compile-grid.mjs  --fn "x > y + 3 ? 1 : y > x + 3 ? 2 : 0" --name grid
node scripts/compile-fsm.mjs   --fn "[s & 1, x ? (s ^ 1) & 1 : s & 1]" --nIn 1 --nState 2 --nOut 1 --name blinker
```

每条命令加 `--help` 看全部参数。

## 表达式程序

给输入起名字、定位宽，用表达式写出每个输出：

```
node scripts/compile-expr.mjs --spec examples/thermostat.expr.json --name thermostat
```

```json
{
  "inputs": { "temp": 7, "target": 7, "heating": 1 },
  "let": { "cold": "temp + 2 < target", "warm": "temp > target + 1" },
  "outputs": {
    "heat": { "width": 1, "expr": "cold || (heating && !warm)" },
    "error": { "width": 7, "expr": "temp > target ? temp - target : target - temp" }
  }
}
```

语义刻意定得简单、没有歧义：

- 值是**精确整数**，中间结果不会溢出；每个输出取值对 2^位宽 取模，负数按补码回绕，和硬件一致。
- 运算符与优先级照 JavaScript：`?: || && | ^ & == != < <= > >= << >> >>> + - * / %`，一元 `~ ! -`，位切片 `a[3]`、`a[7:4]`，常数可写十进制、`0x`、`0b`。
- 输入按声明顺序从最低位开始排，总共不超过 20 位；证书的 `expression` 字段写明每个名字占哪几位。
- 写不出确定电路的式子在编译前就报错，并指出位置：除数可能小于 1、`>>>` 作用在可能为负的值上、未知名字、位切片高低位写反等。

**记忆。** 要记住东西的行为（计数、开关、「连续三次」）加 `state`：每个状态值存在 LATCH 里，开机是 0，每一拍变成它的 `next`。例子里 `given` 可以写当前状态，`then` 写这一拍之后的状态：

```json
{
  "inputs": { "press": 1 },
  "state": { "count": { "width": 4, "next": "press ? (count == 9 ? 0 : count + 1) : count" } },
  "outputs": { "digit": { "width": 4, "expr": "count" } },
  "examples": [ { "given": { "press": 1, "count": 9 }, "expect": { "digit": 9 }, "then": { "count": 0 } } ]
}
```

`examples/counter.expr.json` 编出 36 NAND + 4 LATCH，32 个（输入，状态）组合全部复核；页面上按「时钟一拍」能看到 0 到 9 再回到 0。

编译器同时走两条路：一条照旧把整张表交给 BDD；另一条**按表达式的结构**直接生成门——`+` 是行波进位加法器，`*` 是列压缩阵列乘法器，`<` 是借位链，变量移位是桶形移位器，常量沿途折叠、相同的门只建一次。两个起点都在全表上逐行核对，取小的那个去退火，证书的 `synthesis.startsConsidered` 记下两边的门数。结构编译出错的起点会被丢弃，所以它只能让电路变小，不会让电路变错。一般的除法（除数不是 2 的幂的常量）暂时不按结构编，只走表。

`compile-table --fn` 给的式子如果恰好是这门语言能读的（输入叫 `x`），也会自动多一个结构起点；立即执行的函数之类读不了的，照旧只走表。

2026-09-17 实测（0.6.0，默认参数，`node tools/bench.mjs`）：

| 表 | 输入位 | 0.5.0（只有 BDD） | 0.6.0 | 起点 |
|---|---|---|---|---|
| 8 位加法器 | 16 | 161 NAND | 68 NAND，1.2 秒 | 表达式 |
| 10 位加法器 | 20 | 518 NAND | 86 NAND，1.2 秒 | 表达式 |
| 10 位比较器 | 20 | 95 NAND | 71 NAND，0.8 秒 | 表达式 |
| 4×4 乘法器 | 8 | 278 NAND | 124 NAND | 表达式 |
| 5×5 乘法器 | 10 | 874 NAND | 210 NAND | 表达式 |
| 6×6 乘法器 | 12 | 2,673 NAND | 318 NAND，1.1 秒 | 表达式 |
| 恒温器（上面的例子） | 15 | 436 NAND 起步 | 247 NAND，2.1 秒 | 表达式（起步 292） |

基准固定种子 1，所以 0.5.0 列和上面「宽表」里按默认种子测的数不完全一样。16 张表合计从 10,170 NAND 降到 6,440。奇偶、数 1 的个数、随机表写成的是 JavaScript 函数，读不成表达式，结果不变。

**一句话 → 电路。** gatecraft 不调用、也不代付任何模型，用你自己的：

- 图形界面表达式页的「用一句话描述」：填你自己的 API key（Anthropic，或任意 OpenAI 兼容接口，包括本机模型服务），点「问模型」；或者生成提示词，复制到你已经在用的聊天助手里，再把回复贴回来。key 只从浏览器直接发给你选的服务商，默认不保存。
- 命令行：`ANTHROPIC_API_KEY=… node scripts/describe.mjs "两个 6 位数，输出较大的那个" --name max6` 写出 `max6.expr.json`；加 `--provider openai --base-url … --model …` 换服务商，`--prompt-only` 只打印提示词。

**怎么知道程序就是你那句话的意思。** 逐行证明只能保证电路和程序一致，所以程序和那句话之间另有三道关：

1. **例子**。程序可以带 `"examples"`：给这些输入，应该得到这些输出。模型被要求从那句话推出 3 到 6 个例子（你在话里给的例子必须包含在内），和程序互相对照；对不上就把哪个例子错了告诉模型、再问一次。编译时每个例子再核一遍，有一个不成立就不编译；页面上每个例子旁边标 ✓ 或 ✗，你自己加的例子也一样。
2. **读回**。页面把程序翻成大白话，例如「heat（1 位）= cold 或者（heating 并且 不是 warm）」，混用「并且 / 或者」时一律加括号，不会读出歧义。
3. **截断提醒**。输出位数装不下算出来的值时（比如 8 位的和其实会到 510），页面按每一行实际算出的范围提醒你，不会因为分析得粗而误报。

2026-09-18 用一个真实模型（grok 命令行）实测 18 句日常中文（加上一句太含糊的，共 19 句），从一句话一路编到逐行证明过的电路，**18 句的行为全部正确**：

- 12 句普通的，例如「三个人投票，每人一位，1 表示同意，多数同意就通过」6 NAND；「两个 8 位数的平均数，四舍五入」模型写出 `(a + b + 1) / 2`，102 NAND；「一个 8 位数的平方根，向下取整」写成一串比较，65 NAND。
- 2 句没说位数的：「两个数谁大就输出谁」「温度超过 30 度就开风扇」。
- 3 句要记忆的：按钮计数器（0 到 9 循环）、按一下亮再按一下灭、连续三个 1 就报警，用 20 段随机输入序列从开机跑起逐拍对照。
- 1 句故意先塞给模型一个写反的程序（输出较小的那个）：模型看到哪些例子不成立后，第 2 次改对。

其余 17 句都是第一次就对。

**用本机模型、不花钱也能跑通。** 2026-09-18 在这台电脑上装了 Ollama 和 qwen2.5-coder 3B，页面里服务商选「OpenAI 兼容接口」、地址填 `http://127.0.0.1:11434/v1`、模型填 `qwen2.5-coder:3b`、key 留空，输入「三个人投票，每人一位，多数同意就通过」：20 秒后模型通过 HTTP 写回程序和 6 个例子，全部核对通过，点「编出电路并证明」得到 6 NAND，8/8 行复核。启动本机服务时要允许页面的来源：`OLLAMA_ORIGINS=http://127.0.0.1:4747 ollama serve`。

话说得太含糊时，模型不猜，而是反问一句，页面把问题显示出来，你补进那句话里再问。同一轮测评里「帮我做一个灯」得到的是反问「这个灯是开关控制、按一下切换，还是一直亮着？」，而上面 18 句仍然直接编出了电路，没有因为能反问就变得爱问。复测：`node tools/nl-eval.mjs --cmd <模型命令行> --arg=<参数>`（参数以 `-` 开头时必须用等号，例如 `--arg=-p`）。

例子的格式：

```json
"examples": [ { "given": { "a": 3, "b": 5 }, "expect": { "larger": 5 } } ]
```

## 图形界面

```
npm run ui        # 然后打开 http://127.0.0.1:4747/
```

打开就是给普通人用的四步：

1. **说一句话**：在大输入框里写这颗电路要做什么。右边四句（投票、按钮计数器、比大小、开关灯）有现成的程序，点了就走，不用 key；自己写的新句子要用你自己的模型，右上角的模型设置里填 API key（Anthropic 或任意 OpenAI 兼容接口，本机模型不需要 key），或者复制提示词到任意聊天助手再把回复贴回来。说得太笼统时，模型会先反问。
2. **核对**：「它理解成了这样」把程序翻成大白话；「拿例子核对一下」每个例子标 ✓ 或 ✗，可以加你自己知道答案的例子。有例子对不上时，「造出电路」按钮不可用，要么删掉写错的例子，要么回去改那句话。
3. **证明**：显示多少种输入（有记忆时是输入和状态的组合）全部在电路上核对过、多少个与非门和存储单元、多少个例子成立；有电路缩略图，可以下载四个产物。
   - **想做成真的芯片，就交给厂子**：下载一个导入文件（或者复制），到 [tapeout.firsto.ai 的流片页](https://tapeout.firsto.ai/tapeout) 导入 —— 它直接从文件里读出引脚数和门数，你在那边连自己的钱包流片。钱和交易都在那边，gatecraft 不碰钱包、不发交易。
   - **也可以先变成一个应用**：「变成一个应用」卡片可以直接在页面里预览（服务器临时接一下，因为浏览器的 blob 会继承页面的安全策略、把应用自己的样式挡掉），或者下载那一个 HTML 文件发给别人。
   - 折叠起来的「换别的厂子，或者自己来」里：BLIF 网表（通用格式，tapeout.net 的画布、Yosys、ABC、SIS 都认），以及原来的未签名流片单（读你指定的链、写出交易让你核对签名）。
4. **试用**：1 位的输入是大开关，多位的输入用加减按钮，有记忆时按「时钟走一拍」。下面的电路图是真正会被流片的那份网表在一个门一个门地跑，此刻为 1 的连线亮起来，引脚按程序里的名字标注。**点图里任意一个门**，它会告诉你此刻在算什么（「这个与非门：cou0 是 0，pres 是 1，所以输出 1」）；有记忆的电路还会列出**接下来八拍**，输入保持不变时状态和输出怎么走。

页面还会：

- **自动找本机的模型**。开机时探一下常见的本机模型服务（Ollama、LM Studio、llama.cpp 的 OpenAI 兼容口）。探到就直接能问，**不用填任何 key**；探不到才要你填 key 或复制提示词。实测：本机 Ollama 跑 qwen2.5-coder:3b，输入「A lamp: press once to turn it on, press again to turn it off」，它写出了带记忆的程序。
- **记住你造过的电路**。首屏右边「这里造过的」列出名字、门数和那句话；点一个就把它的程序放回编辑器，连种子和步数都是原来的，再造一次就是同样的字节。
- **刷新不丢**。上次的电路（4,096 行以内）会在打开页面时按原来的种子和步数自动重造，四个步骤都能直接点回去。

右上角还有「作品」：能做的八个现成形状 + 你这台机器造过的电路，每一张卡片点「看它跑起来」就当场编译、证明，并把它作为一个应用跑给你看（可以直接下载那一个文件）。

右上角「工作台」是原来的完整界面：表达式、决策图、真值表、状态机四种编辑器，编译参数（步数、种子、优化目标），以及未签名流片单。

服务器只监听 127.0.0.1，只提供 `ui/`、`src/`、`examples/` 三个目录。页面除了这台服务器和你填的 RPC，不连接任何地方；不连钱包，不碰私钥，不发送交易。

## 接到 DeepSeek Harness（骨架已建，可选）

`dsh/` 是一个薄插件层，把这台机器上已有的插件框架当**载体之一**：agent 拿到三个工具（`gatecraft_compile`、`gatecraft_check`、`gatecraft_simulate`），页面和 API 挂在它的 web 地址的 `/gatecraft/` 下。在那里不需要 API key——harness 的 agent 本身就是模型。

这一层是加法：不装插件，上面所有功能照旧。

## 用哪个模型都行

服务商是一张表，不是写死的两家：Anthropic 用它自己的接口，其余全走 OpenAI 兼容口径，所以加一家只是加一行。现在表里有 Anthropic、OpenAI、DeepSeek、月之暗面（Kimi）、智谱（GLM）、阿里云百炼（通义千问）、Groq、OpenRouter，以及「这台电脑上的模型」（Ollama / LM Studio / llama.cpp，自动探测，不用 key）。

页面的模型设置里有「测一下浏览器能不能直连」：用你填的 key 发一次，拿到服务商自己的回话（哪怕是 401）就说明这条路通。2026-09-18 在这台机器上实测：Anthropic、OpenAI、DeepSeek、Kimi、智谱、Groq、OpenRouter 都直接回了 401（能直连）；阿里云百炼超时（可能是网络，不一定是它拒绝）。**连不上的服务商照样能用**——复制提示词那条路在哪都行。

模型名留空的服务商会让你自己填，而不是替你编一个可能不存在的默认值。

## 链上算的和你手里的一样

流片过的电路不只是存在链上，**还能在链上被运行**：TapeOut 的电路合约有 `circuitInfo(id)`、`netlist(id)`、`eval(id, 输入)`、`step(id, 状态, 输入)` 四个只读函数。所以「你手里的应用和链上算的一样」不是说法，是能验的：

```
node tools/chain-eval-check.mjs --rpc https://bsc-dataseed.bnbchain.org \
  --circuits <电路合约地址> --id 5 --rows 24
```

它读出链上的网表、在本地解码、再抽若干行让链上和本地各算一遍逐位对照。**全程只读**：不连钱包、不签名、不发交易、不花钱。API 里对应 `chain.check` 方法。

2026-09-18 实测（BSC 公共节点上的两颗公开电路）：

| 电路 | 链上说 | 本地解码 | 抽样对照 |
|---|---|---|---|
| #1 | 2 输入 1 输出 3 个门 | 3 NAND | 4 / 4 行一致 |
| #5 | 9 输入 5 输出 72 个门 | 72 NAND | 24 / 24 行一致（共 512 行） |

**位是怎么放的**：按位打包、低位在前，一个字节装八位。这一条是实测出来的（前端没有写），所以工具每次会自己再试一遍两种放法；哪天链上改了，它会说「认不出这条链怎么打包」，而不是给你一个错答案。**带状态的电路走 `step`**，逻辑写好也测过（假链），但还没在链上找到一颗带状态的公开电路来实证。

## 本机 API

页面右上角会显示「API · 12 个方法」，点开就是方法清单。没开 API（`--no-api`）时这个按钮不出现。

`npm run ui` 的同一个地址还答应一个本机 API，给这台机器上的其他程序用（约定照本机 dsh 的外接接口：只监听 127.0.0.1、校验 Host、拒绝别处网页的 Origin、方法名用点号分段）：

```
curl -s localhost:4747/api                       # 它答应哪些方法
curl -s localhost:4747/api -d '{"method":"compile.expr","params":{"spec":{
  "inputs":{"a":1,"b":1,"c":1},
  "outputs":{"pass":{"width":1,"expr":"a + b + c >= 2"}},
  "examples":[{"given":{"a":1,"b":1,"c":0},"expect":{"pass":1}}]},"name":"vote"}}'
```

回包统一是 `{"ok":true,"method":…,"result":…}` 或 `{"ok":false,"method":…,"error":{"code":…,"message":…}}`；`code` 是 `bad_request`（400）、`unknown_method`（404）、`unauthorized`（401）、`too_large`（413）、`failed`（422，参数没问题但做不成，例如例子不成立）。

| 方法 | 做什么 |
|---|---|
| `health.status` | 编译器版本、方法清单、步数与请求体上限；并明确写着不持有 key、不签交易 |
| `program.check` | 不编译，只检查一段表达式程序：位宽、每个例子成立与否、大白话读回、几行样例 |
| `program.run` | 给一组具名输入（和当前状态），返回输出和下一拍的状态 |
| `program.table` | 程序对应的完整表（不超过 65,536 行） |
| `compile.expr` / `compile.table` / `compile.grid` / `compile.fsm` | 编译并逐行证明；可选 `steps`、`seed`、`objective`、`name`，`files:true` 连三个产物文件的文本一起给 |
| `circuit.simulate` | 给网表字节和一组输入，跑出输出、下一拍状态，可选每根线的值 |
| `describe.prompt` | 生成那段提示词（**不接受 key，服务器不调用任何模型**） |
| `describe.read` | 把模型的回复读成程序，或者取出它的反问；顺便报例子是否成立 |
| `tapeout.plan` | 读你指定的 RPC，返回**未签名**的流片单（可选 `eth_simulateV1` 模拟） |

### 加你自己的接口

不用改这个仓库：写一个插件，扔进 `~/.config/gatecraft/api-plugins/`（或者 `--plugin 文件`）。插件的形状照本机 dsh 的插件（导出 `name` 和 `apply(ctx)`，注册的东西交给 `ctx`，`ctx.effect` 登记清理）：

```js
// ~/.config/gatecraft/api-plugins/cost.mjs
export const name = "cost";
export function apply(ctx) {
  ctx.method("of", ({ nand, depth }) => ({ podCost: nand * depth ** 3 }));   // POST /api 的 cost.of
  ctx.method("ofProgram", async (params) => {                                 // 可以调内置方法
    const r = await ctx.api["compile.expr"](params);
    return { nand: r.certificate.circuit.nand, podCost: r.certificate.circuit.podCost };
  });
  ctx.route("/cost/ping", "GET", (req, res) => { res.writeHead(200); res.end("ok\n"); });
  ctx.effect(() => console.log("cost: 收摊"));                                 // 服务器关闭时跑
}
```

规矩：

- **方法名自动带插件名前缀**（`ctx.method("of")` → `cost.of`），所以插件既顶不掉内置方法，也撞不到别的插件；路径同理，必须以 `/插件名/` 开头。
- **一个插件出问题不会拖垮服务器**：加载失败、没导出名字、名字重复、注册时抛错，都只打一行原因然后跳过，其余插件和内置方法照常。
- **护栏一视同仁**：插件的方法和路径同样要过 Host、Origin、`sec-fetch-site` 和 token 检查。抛 `ctx.ApiError("bad_request", …)` 回 400，其他异常回 422（路径里的异常回 500）。
- `health.status` 会列出装了哪些插件、各自加了什么，启动时也会打印一行。
- `--no-plugins` 一个都不加载。

`examples/` 目录本来就由这个服务器提供，所以现成的例子直接 `curl -s localhost:4747/examples/vote.expr.json` 就能拿。

想加一道门：`npm run ui -- --token 你的口令`，之后 `/api` 需要 `authorization: Bearer 你的口令`（或 `x-gatecraft-token`）；`--no-api` 则只提供页面。

## 产物

每次编译在 `out/<name>/` 留下六个文件：

- `circuit.netlist.json`：输入、输出、状态位数，门数、深度，网表字节（`netlistHex`）和元件列表。
- `circuit.certificate.json`：表的 SHA-256、合成与退火前后的门数、复核行数与方法、复现用的 `seed` 和 `steps`。
- `table.json`：被编译的完整表。
- `circuit.firsto.json`：[tapeout.firsto.ai](https://tapeout.firsto.ai/tapeout) 的流片导入文件（**推荐走这个**：2026-09-18 在它站上实测，导入后它读出的门数和证书一致；BLIF 那条路它会把反相器和输出缓冲重新算成独立门，同一个计数器从 35 门变成 47 门）。字段就是它的导入器允许的那五个（`schema`、`processor`、`nIn`、`nOut`、`netlist`），多一个字段它会拒绝，所以这份只写那五个；`netlist` 就是规范的 `0x` 网表字节。
- `app.html`：**这颗电路作为一个能用的网页应用**。一个自带一切的单文件（7–9 KB）：电路在里面跑，控件按程序里的名字命名（1 位是开关和灯，多位是加减和读数），有记忆时带「走一拍 / 自动走 / 回到开机状态」，证明结果印在页眉上。双击就能打开，不联网、不依赖任何东西，可以直接发给别人。
- `circuit.blif`：同一颗电路的 BLIF 网表，厂子自己的工具认这个格式（Yosys / ABC / SIS，tapeout.net 的画布也直接导入）。引脚按程序里的名字命名（`x0_press`、`y4_nine`、`s0_count0`），触发器一律从 0 开始，常量不写成零输入的 `.names`（有的导入器只接受一到两个输入的表），而是用 `NAND(x, 非 x)` 现搭出来。`tests/blif.test.mjs` 用一个独立的 BLIF 读取器把它读回来，在每一行上和电路对照。

## 可复现

退火的每一个随机选择都来自带种子的生成器，预算按步数而不是秒数计。不传 `--seed` 时种子取自表的哈希，所以同一张表在任何机器上编译两次，网表和证书都逐字节相同。默认 200,000 步；表特别大时自动减少，实际步数写在证书里，用 `--seed` 和 `--steps` 传回去就能复现。证书里的 `compiler` 字段记着编译器版本：换了版本，同样的种子不一定得到同样的电路。

## 宽表

BDD 的大小强烈依赖变量顺序，编译器分三步选：
1. 先试几种候选顺序：自然顺序、反序、按种子打乱的顺序。
2. 对其中节点最少的那个做 sifting：一次挪一个变量，把它放到让图最小的那一层。
3. 最后按实际生成的 NAND 数挑最小的方案，所以 sifting 只在确实变小时才被采用。

退火的每一步只重算被改动那个门的扇出锥，某个门算完值没变就不再往下推，第一个输出对不上就立刻放弃这一步；表宽过 16 位时，先在均匀取样的几千行上试算，那里已经错了就不再算全表。每一步的判决和全量重算完全相同（有测试逐字节对照），但宽表上快 20 到 33 倍，省下来的时间用来多搜：16 位以内的表拿到的步数是原来的 20 倍。更宽的表上，保持电路精确的那些步仍然要在全表上验证，所以步数随表宽缩小，编译时间不比以前长；想要更小的电路，自己加 `--steps`。

没有补边的 BDD 会把一个函数和它的否定存成两套节点，而加法器的进位链、计数、奇偶这类 XOR 密集的函数里到处是这种成对的节点（实测 61%–93% 的节点，它的否定也是一个节点）。发射时，一对里先建出来的那个走正常的 mux，另一个只要一个非门。

2026-09-17 实测（0.5.0，默认参数，耗时含全空间复核）：

| 表 | 输入位 | 结果 | 耗时 |
|---|---|---|---|
| 8 位加法器 | 16 | 109 NAND（0.4.0 版 140，0.3.0 版 320，0.2.0 版 1,323） | 1.8 秒 |
| 9 位加法器 | 18 | 425 NAND（0.2.0 版 9,116，耗时 57 秒） | 0.6 秒 |
| 10 位加法器 | 20 | 518 NAND，1,048,576/1,048,576 行 | 1.0 秒 |
| 10 位比较器 | 20 | 98 NAND | 1.3 秒 |
| 16 选 1 | 20 | 49 NAND | 0.9 秒 |
| 20 位数 1 的个数 | 20 | 787 NAND（0.4.0 版 1,055） | 0.9 秒 |

随机表这类函数，换什么变量顺序 BDD 都很大，门数主要受合成方式本身限制。乘法器以前也是这样（只走表时 6×6 乘法器 2,665 NAND），用表达式写就改走结构编译，见「表达式程序」。在这类表上多退火帮助有限：6×6 乘法器给 20 万步也只从 2,733 降到 2,667，12 输入的随机表几乎不动——两千多个门的网表里，随机改一根线撞上有用改动的机会太小。要大幅变小得换合成方式，不是多搜。

## 决策

一个普通程序（游戏、店、门禁）照常是程序；**只有它的决策过电路**。一个决策读几位观测、给几位动作，天然装进一次证明。

规则写得出来的，上面的表达式路已经够了。这条路是给**写不出规则、但每种情况人能认出答案**的判断准备的：把每种情况用人话问一遍，答案就是真值表，编译器把它冻结成逐行证明过的电路，人只看把握低的那些行。

决策文件（`examples/mario-jump.decision.json`、`examples/comment-hold.decision.json`）里有一份 **codebook**：每个观测字段的位宽，以及**每个合法编码的一句人话**。**没有人话的编码就是非法编码**——这些行永远不拿去问，电路对它们的答案是安全动作 + `review = 1`，**由表构造出来，不来自任何模型的判断**。

```
node scripts/decide.mjs draft     --from "一句话说清这个决策" --out DIR   # 起草 codebook，读回给你看
node scripts/decide.mjs fill      --spec d.json --with rule|chat|jev [--asks-per-row 3]
node scripts/decide.mjs freeze    --spec d.json [--anchors a.json]   # 编译 + 逐行证明 + 证书 + review.json
node scripts/decide.mjs check     --out DIR                          # 让 Yosys 独立再证一遍

node scripts/decide.mjs ask       --spec d.json --out DIR --count 20   # 逐题问你，不显示模型答案
node scripts/decide.mjs calibrate --spec d.json --out DIR --anchors answered.json
node scripts/decide.mjs export    --spec d.json --out DIR            # 一个可直接 import 的文件
```

### 填表用什么

三条路，哪条都能走完整个流程：

- `--with rule`：用 spec 里（或 `--rule` 给的）一条规则，免费、确定。
- `--with chat --asks-per-row 3`：用普通对话模型（命令行走本机的 opencode），每种情况问三遍，**把握度 = 三次答案一致的比例**。页面上同一件事用你在页面里配的模型做；MCP 里就是你的 agent。
- `--with jev`：带校准概率的决策模型，可选。注册一次 [typesafe.ai](https://typesafe.ai)，然后：

```
printf '%s' '你的key' > ~/.config/gatecraft/jev.token && chmod 600 ~/.config/gatecraft/jev.token
```

**gatecraft 不调用、不代付任何模型**，key 只作为请求头发给你选的那家。也支持 `TYPESAFE_API_KEY` 环境变量，或者走 Cloudflare Workers AI（`cloudflare.account` + `cloudflare.token`）——同一个模型，两条路实测答案一致。实测 56 个决策、24,945 次调用合计约 0.5 美元，一个决策约 1 美分。

`draft` 不是让模型替你拍板：它起草，`parseDecision` 判形状，**然后把 codebook 用人话读回来给你过目**，并标出该看的地方——**闻着像跨过那堵墙的桶**（要读文字、要认人、要联网、要看时钟），以及 **`safe` 选得对不对**（实测模型倾向把它读成「最不意外的那个」，而不是「万一被误执行、后果最受得起的那个」）。`review --spec d.json` 可以随时对已有文件做同样的读回。

**⚠️ 第 4、5 步不是可选的严谨，是闸。** 实测：**盲答过锚点的 6 个决策里有 2 个，填表模型在它最有把握的地方也和盲答不一致**——而那 2 个**通过了前三步的全部检查**（逐行证明、Yosys、可复现、高把握）。**只有锚点能发现。**（那些盲答目前是 AI 助手作为独立判断者写的，还没有真人答过，见 [findings](findings.zh-CN.md) 第 5 条。）

`calibrate` 给三种裁决之一：

| 裁决 | 含义 |
|---|---|
| `delegate` | 可以交，门槛定在这里，它决定 X%、其余递给人 |
| `write-the-rule-instead` | 能交，但现成规则就能对上——写个 if 更便宜 |
| `do-not-delegate` | **任何门槛下它要执行的行都和人不一致。`export` 会直接拒绝导出。** |

最后拿到的是一个 **4 KB、零依赖、不联网、不起服务**的文件：

```js
import { decide } from "./comment-hold.decision.mjs";
const { action, review } = decide({ tone: 2, target: 1, provoked: 0, history: 0, stakes: 0 });
if (review) handToAPerson(); else actOn(action);
```

里面装的是**表**不是网表——证明的全部内容就是「电路在每一行都等于这张表」，所以装表就是装被证明过的行为，而且查表比模拟门快。测试里拿导出的模块和**模拟真实与非门**逐行比对过，256/256 一致。文件头还带着它的政策核对结果；**没做过锚点的，头部明写「没有人核对过」**。

电路输出 = 动作编码位 + 一个复审位。复审位为 1 的情况：非法编码、没答上来、把握低于门槛且没人确认过。人的改动写在 `overrides.json` 里，盖着 codebook 哈希，换了 codebook 就拒绝套用。

**老实话**：`--with jev` 用的是返回校准概率的决策模型；`--with chat` 用的是普通对话模型，**它的把握是自己写的一个数**。实测在一个真有争议的决策上，同一个模型问两遍只有 75% 答案一样，单次高把握的行也只有 70% 能复现——所以那条路要配 `--asks-per-row N`（问 N 遍取多数），而且**别把它当成可以照着执行的政策**。数字和边界见 [findings](findings.zh-CN.md)。

## 优化目标

退火默认让 NAND 最少，因为补铸代币是按 NAND 个数付钱的，但这样深度可能变深。加 `--objective cost` 就改为让 PoD 成本 `(元件数 + 6×LATCH) × 深度³` 最低（页面上对应「优化目标」），证书的 `reproduce.objective` 会记下这个选择。不加这个参数时，证书和以前逐字节相同。

2026-09-17 实测（0.5.0，默认种子和步数）：

| 电路 | 按门数（默认） | 按成本 |
|---|---|---|
| grid-demo | 36 NAND，深度 15，成本 121,500 | 40 NAND，深度 12，成本 69,120 |
| 4 位加法器 | 36 NAND，深度 21，成本 333,396 | 46 NAND，深度 18，成本 268,272 |

**种子影响很大，这是退火的本性。** 同一张 4 位加法器的表，只换种子，按门数的结果就在 32 到 55 NAND 之间（10 个种子，中位数 43）。默认种子取自表的哈希，所以同一张表每次结果相同，但未必是最好的那个。

在意门数时，多给步数比多试种子更划算。同样多花 4 倍算力，一次跑 4 倍长胜过跑 4 次取最好；把同样的步数拆成几次独立起跑则更差（4 位加法器拆成 4 次，中位数从 43 变成 47）。步数的收益是平滑的对数曲线，320 万步还在下降，没有拐点。2026-09-17 实测（6 个种子的中位数，单次耗时）：

| 表 | 20 万步（默认） | 40 万 | 80 万 | 160 万 | 320 万 |
|---|---|---|---|---|---|
| 4 位加法器 | 43，0.3 秒 | 35 | 34 | 33 | 32，5.4 秒 |
| 3×3 乘法器 | 63 | 57 | 55 | 52 | 49 |
| 4×4 乘法器 | 272，0.5 秒 | 250 | 247 | 221 | 209，12.4 秒 |
| 6 输入随机表 | 166 | 161 | 154 | 149 | 142 |

默认步数没有因此调高：那是**跨种子的平均**，落到某一张具体的表和它的默认种子上往往看不出来——自带示例里（0.4.0 时测），4 位加法器 20 万步和 80 万步都是 40 NAND，grid-demo 只少 1 个，却都慢了 4 倍。所以默认保持快，要更小的电路自己加 `--steps`，证书会记下用了多少步。

## 状态电路缩小

`node scripts/anneal-stateful.mjs <模块> <导出函数名> --name NAME` 接受一个已有的 NAND + LATCH 电路：把每个 LATCH 拆成一个额外输入和一个额外输出，对完整的（输入，状态）表退火，按原来的 LATCH 顺序包回去，再逐组合复核。前后按同一口径计数（网表里实际的 NAND 个数），结果不比原来小就不输出，退出码为 2。用 `tests/fixtures/stateful-examples.mjs` 里的例子实测：

- 1 位翻转器：6 → 5 NAND；
- 写得冗余的 2 位计数器：16 → 10 NAND；
- 1 位延迟线：2 NAND 已经是最小，拒绝输出。

## 流片单

```
node scripts/tapeout-manifest.mjs --netlist out/counter/circuit.netlist.json \
     --rpc <RPC 地址> --processor <处理器合约地址> --from <你的钱包地址> \
     [--chain-id 56] [--expect-implementation <实现合约地址>] [--skip-simulation] [--out plan.json]
```

它在同一个区块上读取以下数据，然后生成按顺序签名发送的未签名交易（先补铸缺少的 NAND/LATCH 代币，再调用 `tapeout`）：
- 流片费；
- NAND/LATCH 代币的单价和协议费；
- 代币的供应上限和已铸数量；
- 你的 NAND、LATCH 和原生代币余额；
- 最近发出的电路编号。

写出之前，它用 `eth_simulateV1` 在同一个区块上把这些交易按顺序模拟一遍，要求三条都满足：
- 每笔都成功；
- 流片返回的电路编号等于预计编号；
- 处理器记录的元件数和状态位数与网表一致。

任何一条不满足就不写文件，退出码为 2，并说明哪一笔会因为什么失败。RPC 不支持模拟时报错，可以加 `--skip-simulation` 跳过。

以下情况会直接拒绝：
- `--chain-id` 或 `--expect-implementation` 不对；
- 缺的代币超过合约还能铸的数量。代币铸满时，要先从别处拿到代币。

所有地址都是参数，工具不持有私钥，也不广播任何交易。

2026-09-15 在 BSC 主网上做过只读实测，不签名，不广播：
- 两个不同实现的节点读数一致；
- 在代币已铸满的处理器上，工具会拒绝，并给出剩余数量；
- 在模拟里给发送者补足代币后，流片成功，返回的编号是 `nextId()` 加 1，TapedOut 事件记录的元件数等于 NAND 加 LATCH。

- 各个编译器的往返测试；
- 状态电路的缩小与拒绝；
