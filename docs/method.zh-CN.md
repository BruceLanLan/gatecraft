# 工作原理

中文 · [English](method.md)

这一页讲方法：每一步做什么、保证什么、为什么这样设计。每个设计选择背后的测量见 [findings](findings.zh-CN.md)。

## 一段话说清楚

一个程序如果每次都调模型来做同一个小决策，大约四分之一的时候会得到不一样的答案，每次调用都要花钱，而且说不清它为什么这么判。gatecraft 的做法是：把程序可能处在的**每一种情况**都问一次，答案写成一张表，把这张表编译成一颗与非门电路，再用两套独立的方法证明电路在每一行上都等于这张表。然后让**人**在看不到模型答案的情况下回答其中二十种情况，用这些答案来判断：这个决策到底该不该交出去。

## 那堵墙：观测必须本来就是编码

gatecraft 不读文字、不认人、不看时钟、不联网。这些由调用它的程序去做，然后交给 gatecraft 几个小编码：档位、等级、状态、分好桶的读数。把原始值分成编码是调用方的事，不在证明范围内。

这是这个工具最硬的一条边界，而且是刻意的：它恰好就是随口许愿失败的地方（文字、清单、时间、身份、联网——见 [findings 第 4 条](findings.zh-CN.md#4-人们随口许的愿望几乎都装不进电路)）。

## 第 1 步：codebook

决策文件写明每个观测字段、它占几位，以及**每个合法编码对应的一句人话**：

```json
{
  "name": "comment-hold",
  "question": "What should be done with this comment?",
  "observe": {
    "tone": { "width": 2, "raw": "how the comment is written", "values": { "0": "calmly stated", "1": "sarcastic or mocking", "2": "openly abusive" } },
    "provoked": { "width": 1, "raw": "1 when it replies to a comment that attacked this author", "values": { "0": "unprompted", "1": "a reply to an attack" } }
  },
  "act": { "choices": { "keep": "leave it", "fold": "fold it behind a click", "remove": "take it down" }, "safe": "keep" }
}
```

- **没有人话的编码就是非法编码。**电路对它的回答是 `safe` 动作加 `review = 1`，这是表的构造决定的，不涉及任何模型的判断。
- **`safe` 是「万一被误执行、造成损害最小」的那个动作**，不是最常见的那个。模型起草 codebook 时往往会选「最不意外」的那个；读回时这一项每次都会被拎出来提醒。
- codebook 有哈希。后面的一切（填好的表、人工改动、锚点、导出的模块）都带着这个哈希，codebook 对不上就拒绝使用。

codebook 可以用一句话让你自己的模型起草。草稿随后会**被读回成人话**，并标出要检查的地方：看起来需要读文字、认人、看时钟或联网的桶；没说数据从哪来的桶；以及 `safe` 动作。位宽放不下它自己编码的，会自动放宽并报告出来——那是算术，不是判断。

## 第 2 步：填表

每一种合法情况都回答一次。三种方式，哪一种都能走完后面的流程：

| 来源 | 是什么 | 把握度 |
|---|---|---|
| 规则 | 一个关于各字段的表达式 | 精确，每一行都确定 |
| 你自己的模型 | 你在页面上配的模型、通过 MCP 接入的 agent，或命令行里的对话模型 | 问三遍的**一致率** |
| Jev（可选） | 返回校准概率的带类型决策模型 | 模型给出的概率 |

实测对话模型自报的把握度没有信息量，而它和自己一致的比例有（[findings 第 2 条](findings.zh-CN.md#2-对话模型自报的把握度没有信息量它和自己一致的比例才有)）。问三遍、默认门槛 0.7 时，只有三次全一致的行才会直接执行。

不内置任何人的 key。你自己的模型花的是你自己的账；页面是在浏览器里直接连你的服务商，本机服务器看不到那个 key。

## 第 3 步：冻结与证明

填好的表就是电路的规格。每一行的输出是动作编码，再加一个**复审位**：情况非法、没答上、或者答案把握度低于门槛时，复审位为 1。

这张表先编译成与非门（先用二元决策图，再用模拟退火把它压小），然后证明两次：

1. **在本机逐行证明。**2ⁿ 个输入每一个都在门上模拟一遍，和表逐行比对。
2. **由 Yosys 独立证明。**表和电路都写成 BLIF，Yosys 用 miter 加 SAT 求解器证明两者相等。故意改坏一个门，这个证明就会失败——这一点有测试。

证书记录 codebook 哈希、填表哈希、门数和检查过的行数，也写明它**不保证**什么：证明只说明电路等于表，完全不说明这张表是不是谁想要的政策。

## 第 4 步：二十道盲答（锚点）

按填表结果的把握度分层抽出二十种情况，用 codebook 里的原话交给**人**来答，全程不显示模型的答案——人一旦知道机器怎么答，就是在附和它，而不是在判断。几个答案都说得过去时可以都选；真有争议的可以跳过，跳过绝不会被算成同意。

这是唯一能抓出「模型自信地做错」的一步，而且没法自动化：两个模型之间的一致率，和一个模型自己的一致率差不多，所以让模型来答锚点，等于把「正确性检查」又变回了「一致性检查」。通过 MCP 校准时必须填 `answered_by`，agent 答的锚点在所有地方都会被标出来，包括导出模块的头部。

## 第 5 步：校准

把把握度门槛从 0.9 往下扫到 0.3。每一档看三件事：这张表会自己决定多少；人的答案里有几道落在它会直接执行的行上；这些里有几道一致。落在上面的答案至少有 5 道、而且**全部**一致的最低那一档，就是校准后的门槛。裁决是下面三种之一：

| 裁决 | 含义 |
|---|---|
| 可以交 | 在这个门槛下交出去；它决定这一部分，其余交给人 |
| 写个 if 更划算 | 安全，但一条写好的规则已经能对上它要决定的 85% 以上——直接写 if |
| 别交 | 要么它在会直接执行的地方和人矛盾（多答也没用），要么落在它会执行的行上的答案还太少（多答几道再重新算） |

用规则填的表，每一行把握度都一样，门槛扫描会收成一档，并且会写明这一点。

## 第 6 步：导出

结果是一个 ES 模块，大约 4 KB，零依赖、不联网、不需要服务器：

```js
import { decide } from "./comment-hold.decision.mjs";
const { action, review } = decide({ tone: 2, target: 1, provoked: 0, history: 0, stakes: 0 });
if (review) handToAPerson(); else actOn(action);
```

里面装的是**表**，不是网表：证明的内容就是「电路在每一行都等于这张表」，所以装表就是装被证明过的行为，而且查表比模拟门快。表按**校准后的**门槛冻结，门槛对不上就拒绝导出。校准结论是「别交」的决策也拒绝导出。模块头部写明这张表有没有和人核对过。

## 注意力的边界

决策上限是 16 位。不是因为证明变难——填 65,536 种情况只要一美元左右——而是二十道盲答分摊到这么多情况上，就不再说明任何问题了（[findings 第 7 条](findings.zh-CN.md#7-决策能做多大取决于人能抽查多少不取决于电路)）。决策要小到二十道题算得上一个真正的样本。

## 预注册

这个工具背后的每一次实验，都在数据出来之前写下：什么结果算支持、什么算推翻、什么算「没有产品」。事后才得到的结果，或者预先写的判据后来发现写得不好，都会和数字一起照实报告——就算有更好看的结论，也报告预先写下的那个。用到的评测工具在 `tools/` 里（比如 `tools/band-score.mjs`、`tools/calibrate.mjs`、`tools/score-rules.mjs`），自带例子用到的锚点在 `examples/*.anchors.json`，每份都附有它是怎么来的说明。
